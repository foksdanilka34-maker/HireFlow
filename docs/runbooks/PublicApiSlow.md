# PublicApiSlow (warning)

**Что значит.** За час меньше 99% успешных (`200`) запросов `POST /v1/screenings` с телом до 2 МБ
(`size="small"`) выполнились быстрее 1 с, при не меньше 20 таких запросах. SLO публичного API — 99% таких
скринингов быстрее 1 с. Большие файлы (`size="large"`), ошибки и отказы по лимиту в SLO не входят.
**Влияние:** внешние клиенты ждут ответа дольше обещанного, у них срабатывают тайм-ауты.

## Как проверить
- Grafana, дашборд «HireFlow», строка «Публичный API»: «Доля быстрых скринингов», «p95 по маршруту»,
  «Запросы в минуту по клиентам и кодам».
- Медленно у одного клиента или у всех (Prometheus):
  `histogram_quantile(0.95, sum by (le, client) (rate(hireflow_public_api_request_duration_seconds_bucket{http_route="/v1/screenings", size="small", status_code="200"}[15m])))`
- Трейсы (Tempo, TraceQL): `{resource.service.name="hireflow-api" && span.http.route="/v1/screenings" && duration > 1s}` —
  видно, где время: извлечение текста, скоринг или SQL квоты.
- Строки журнала запросов в Loki: `{service_name="hireflow-api"} |= "Public API request"` (клиент, маршрут, код,
  длительность; тел запросов там нет).
- Нагрузка: `docker stats --no-stream`.

## Частые причины
- Один клиент шлёт много «тяжёлых» PDF (много страниц, картинки) — извлечение текста занимает CPU.
- Нехватка CPU у контейнера API, в том числе из-за откликов бота в то же время.
- Медленный SQL списания квоты (длинные спаны `postgresql`).

## Что делать
1. Понять по запросу выше, один это клиент или все.
2. Один клиент — связаться с ним; при необходимости уменьшить его дневную квоту в БД (`api_clients.daily_quota`).
3. Нехватка ресурсов — освободить хост или увеличить ресурсы.
4. Медленное извлечение текста или SQL — задача разработчику.

## Когда эскалировать
Доля быстрых скринингов ниже 95% или алерт держится больше 2 часов — разработчику API.
