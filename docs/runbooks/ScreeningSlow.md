# ScreeningSlow (warning)

**Что значит.** За час меньше 99% скринингов (чтение резюме и скоринг при отклике) прошли быстрее 60 с, при
не меньше 10 скринингах. SLO скрининга — 99% откликов быстрее минуты.
**Влияние:** кандидат долго ждёт ответа бота после отправки резюме, бот может не дождаться ответа API.

## Как проверить
- Grafana, дашборд «HireFlow»: «Доля скринингов быстрее 60 с», «p95 длительности скрининга».
- Распределение по корзинам (Prometheus):
  `sum by (le) (increase(hireflow_screening_duration_seconds_bucket[1h]))`
- Трейсы откликов (Tempo, TraceQL): `{resource.service.name="hireflow-api" && duration > 30s}`.
- Нагрузка: `docker stats --no-stream`.

## Частые причины
- Очень большие или «тяжёлые» PDF (много страниц, картинки).
- Нехватка CPU у контейнера API.

## Что делать
1. Проверить, не связано ли с одним типом файлов (трейсы, логи API по `trace_id`).
2. Нехватка ресурсов — освободить хост или увеличить ресурсы.
3. Проблема в извлечении текста — задача разработчику.

Сменили границы корзин гистограммы скрининга (`HireFlowMetrics`) — в течение часа после выкладки доля
считается по старым и новым рядам вперемешку и алерт может сработать ложно: заранее поставить silence на 1 ч
в Alertmanager (http://localhost:9093 → New Silence, `alertname="ScreeningSlow"`).

## Когда эскалировать
Доля быстрых скринингов ниже 95% или алерт держится больше 2 часов — разработчику API.
